# ARC Hub 0.3 — выпуск и проверка на Debian VDS

> Цель: управлять зарегистрированными Windows-компьютерами через ARC Hub из ChatGPT, используя персональные OAuth 2.1 PKCE-сессии. Общих токенов владельца в плагине нет.

## Что работает в исходниках

- ARC Hub: `/healthz`, `/mcp`, `/agent/poll`, `/agent/result`.
- ARC Web: пользователи, устройства, аудит, регистрация ПК, права и тест «Открыть Блокнот».
- OAuth: защищённый MCP-ресурс, discovery по RFC 9728 / RFC 8414, PKCE S256, DCR только для стабильного callback ChatGPT, одноразовые коды, ротация refresh-токенов и ограниченный срок доступа.
- Устройства: разрешения пересекаются между ролью пользователя, Hub policy и локальным согласием Windows Agent. Запуск приложений требует эксклюзивного сеанса на 90 секунд.
- Windows ARC Agent: входящие публичные порты не нужны, используется исходящий HTTPS к Hub.

## Безопасность перед обновлением

1. Сохраните копию `/etc/arc`, текущего `/opt/arc`, текущего `/etc/caddy/Caddyfile` и конфигурации systemd. Не копируйте секреты в репозиторий, ChatGPT или общие папки.
2. Убедитесь, что есть отдельный аварийный доступ к VDS и ПК. Не удаляйте Desktop Commander до успешной проверки через ARC.
3. Проверяйте только домен `https://vpn.homeaicore.ru` и сертификат TLS. Не отключайте проверку SSH-hostkey или TLS.
4. Используйте отдельного пользователя ARC для ChatGPT. Не вставляйте owner/device токены в `mcp.json`.

## Обновление VDS через ARC Web

Если на сервере уже установлен ARC Web и авторизован пользователь `owner`:

1. Откройте [ARC Web](https://vpn.homeaicore.ru/web/) и войдите как `owner`, используя персональный токен **только на этой странице**.
2. Создайте защищённую резервную копию, если её не сделал штатный updater.
3. Нажмите «Обновить сервер» и дождитесь финальной проверки и повторного входа.
4. **Миграция со старого updater может требовать двух последовательных обновлений:** первая установка заменяет сам updater, вторая устанавливает `arc_oauth.py` и `/etc/arc/oauth.env`. Это не повод обходить проверку или запускать вручную необозреваемый скрипт.
5. Проверяйте следующий шаг по наличию авторизационных metadata (ниже). Не считайте сервер готовым по одному `healthz`.

## Публикация с доверенным SSH-доступом

Запускайте строго из проверенной shell-сессии VDS, с уже подтверждённым SSH-hostkey. Используйте штатный установленный updater, а не загрузку случайного `main`-скрипта в root-shell. Для релизов закрепляйте точный коммит GitHub.

Команды проверки после обновления:

```bash
systemctl is-active arc-hub caddy
curl -fsS https://vpn.homeaicore.ru/healthz
curl -fsS https://vpn.homeaicore.ru/.well-known/oauth-protected-resource
curl -fsS https://vpn.homeaicore.ru/.well-known/oauth-authorization-server
curl -i https://vpn.homeaicore.ru/mcp
```

Ожидается:
- `arc-hub` и `caddy` в состоянии active;
- `healthz.status=ok`;
- `resource=https://vpn.homeaicore.ru/mcp`;
- `issuer=https://vpn.homeaicore.ru`;
- `code_challenge_methods_supported` включает `S256`;
- GET `/mcp` — `405 Method Not Allowed` (только POST).

Для регистрации OAuth-клиента ChatGPT используется `https://chatgpt.com/connector_platform_oauth_redirect`. Не разрешайте произвольные redirect URI.

## Включение Asus для открытия Блокнота

1. На Asus локальный конфиг `%LOCALAPPDATA%\ARC\agent.json` должен иметь `permissions.apps=true`. `input`, `shell`, `write` оставьте false.
2. Убедитесь, что локальный `ARC-Agent.exe` автоматически запускается и `http://127.0.0.1:8896/healthz` отвечает `ok`. Локальный порт не открывайте в интернет.
3. В ARC Web выберите Asus; владельцу доступна кнопка «Разрешить запуск приложений». Для применения введите точное имя компьютера и подтвердите. Сервер выдаст `apps.launch` только владельцу; второй пользователь не получает его автоматически.
4. Веб-панель: «Получить управление» → «Открыть Блокнот» → «Освободить».
5. ChatGPT: подключите приватный плагин ARC через персональный OAuth → `arc_devices` → `arc_permissions` → `arc_take_control` → `arc_call` с `tool=open_notepad`, `arguments={}` → `arc_release_control`. Все вызовы должны указывать точный `device_id`.

Не включайте управление экраном, клавиатурой, файлами и shell без отдельного намеренного согласия и дополнительной проверки.

## Резервное восстановление

Если OAuth discovery не отвечает, проверьте `journalctl -u arc-hub -n 100 --no-pager` и `/var/backups/arc/`. Updater обязан откатывать код, настройки Caddy и systemd при провале health checks. Приватный `/etc/arc/registry.json` и персональные учётные записи не следует уничтожать при откате. До восстановления рабочей пары `ARC Hub ↔ Asus` сохраняйте резервный удалённый доступ.

## Критерии готовности

- Успешный GitHub Actions CI (Linux: Python, Bash, JS, unit/integration tests).
- Публичный HTTPS discovery и OAuth Authorization Code + PKCE проходят проверку.
- Новый плагин ARC 0.2.0 подключён персональным аккаунтом.
- Asus виден в `arc_devices` и запускает Блокнот через `arc_call`, при этом действие записано в аудит.
- Отказ без пользовательских прав и без контрольной аренды подтверждён.
- Перезапуск Hub и Asus не теряет регистрации и не раскрывает токены.
- Только после этого можно рассматривать удаление Desktop Commander.

**Не маркировать релиз как полностью введённый в эксплуатацию до сквозного теста на реальном VDS и Asus.**
